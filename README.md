# Dochak Prism — VISSIM 시뮬레이션 검증 대시보드 + AI 에이전트

## 한 줄 소개

Prism은 PTV VISSIM 교통 시뮬레이션을 **웹에서 조회·분석**하고, **AI에게 자연어로 시뮬레이션
편집과 실행을 맡길 수 있는** 로컬 대시보드입니다. AI가 수행하는 모든 편집은 전용 검증
계층(가드레일)을 통과해야 하며, 사용자의 승인 없이는 어떤 변경도 실행되지 않습니다.

## 왜 만들었나 — "VISSIM은 조용히 실패한다"

VISSIM은 잘못된 설정을 넣어도 오류를 내지 않고 그럴듯한 결과를 출력하는 경우가 많습니다.
예를 들어:

- 존재하지 않는 객체 번호를 조회해도 오류 대신 빈 값이 돌아오는 API가 있습니다.
- 차로 1개짜리 도로에 용량의 2배 수요를 넣어도 시뮬레이션은 정상 종료되고, 초과 수요는
  화면에 보이지 않는 대기 차량으로 조용히 쌓입니다.
- 평가(evaluation) 설정이 꺼진 상태로 시뮬레이션을 돌리면, 완료는 되지만 결과 표가
  텅 비어 나옵니다.

사람이 직접 작업할 때도 놓치기 쉬운 이런 함정을, AI가 작업할 때는 더 놓치기 쉽습니다.
그래서 Prism의 핵심 설계 원칙은 다음과 같습니다:

> **명확한 이유와 함께 거부된 편집이, 숫자가 틀린 채 완료된 편집보다 낫다.**

AI의 능력이 아니라 **검증 계층이 제품의 본체**입니다. 편집 전·후·실행 후 3단계에서
약 50종의 교통공학·VISSIM 제약 조건을 자동 점검하고, 문제가 있으면 실행을 막거나
경고와 함께 결과를 전달합니다.

## 주요 기능

### 1. AI 에이전트 — 자연어로 VISSIM 편집·실행

채팅으로 요청하면 AI가 VISSIM 모델을 직접 읽고, 편집을 제안하고, 승인 후 실행합니다.

- **읽기**: 신호 현시, 차량 입력(수요), 경로 배분, 충돌구간, 감속 구역 등 모델 상태 조회
- **편집**: 신호 주기, 시간대별 수요, 경로 배분율, 충돌구간 우선권, 감속 구역 등
  파라미터 수준의 변경 (현재 v1 — 기하구조 편집은 v2 로드맵)
- **실행**: 다중 랜덤시드 시뮬레이션 실행, 결과 KPI 요약, 차량 궤적 기록

동작 순서는 항상 동일합니다:

```
요청 → AI가 모델을 읽고 편집안 작성 → 사전 검증(가드레일)
     → 사용자 승인 카드 표시 → 승인 1회 = 실행 1회
     → 실행 후 값 재확인(읽기 검증) → 결과·경고 보고
```

승인은 소모성입니다 — 한 번의 승인으로 같은 작업이 두 번 실행되는 일은 구조적으로
불가능합니다. 실행 후에는 변경값을 VISSIM에서 다시 읽어 실제 반영 여부를 확인합니다.

### 2. AI 대시보드 큐레이션

"왜 평균속도가 낮아?"처럼 질문하면, 대시보드가 질문과 관련된 차트·KPI 지표만 골라
보여줍니다. 전체 지표는 버튼 한 번으로 언제든 복원됩니다. 큐레이션이 실패하면 일부만
보여주는 대신 전체를 보여줍니다(반쯤 신뢰할 수 있는 추측보다 전체 공개가 안전).

### 3. 네트워크 렌더링 + 시뮬레이션 재생

- .inpx 파일의 원좌표를 그대로 렌더링: 도로·연결로·차선·신호등·검지기·대기행렬
  카운터 등 11종 요소, 레이어별 켜고 끄기
- 확대/축소에 따라 표식과 부속 시설이 실제 미터 단위 크기로 자연스럽게 전환
  (시맨틱 줌)
- 요소를 클릭하면 해당 객체가 AI 채팅의 컨텍스트로 전달되어 "이 링크의 수요를
  바꿔줘" 같은 요청이 가능
- **차량 궤적 재생**: AI가 실행한 시뮬레이션의 차량 움직임(.fzp)을 네트워크 위에서
  배속 재생

### 4. 베이스모델 검증·비교·보고서

- 관측 교통량(엑셀 업로드) vs 시뮬레이션 결과를 GEH 등 표준 지표로 비교
- 시나리오 간 KPI·방향별 교통량 비교, 보고서 생성·다운로드
- 한국어·영어·일본어 지원

## 어떻게 동작하나 (기술 구조)

```
[브라우저]  Next.js 프론트엔드 (localhost:3000)
     │        대시보드 · 네트워크 뷰 · AI 채팅 · 승인 카드
     ▼
[API]      FastAPI 백엔드 (localhost:8001)
     │        ├─ LLM 계획 루프 (Anthropic Claude) — 도구 선택·관측·재계획
     │        ├─ 가드레일 엔진 — ~50개 제약 카탈로그, 편집 전/후/실행 후 점검
     │        ├─ 승인 게이트 — 서명 기반, 승인 1회당 실행 1회
     │        └─ 작업 큐 — 시뮬레이션은 백그라운드 잡으로만 실행
     ▼
[VISSIM]   PTV VISSIM (COM 자동화)
              원본 훼손 방지: 항상 사본(작업본)에서 편집,
              실행 중인 사용자 GUI에는 절대 접속하지 않음
```

설계상의 안전 장치:

- **원본 보호**: AI는 활성 데이터셋의 .inpx를 직접 수정하지 않습니다. 항상 작업
  폴더에 사본을 만들어 편집하고, 저장은 임시 파일에 쓴 뒤 원자적으로 교체합니다.
- **사용자 GUI 보호**: COM 연결은 항상 새 VISSIM 인스턴스를 띄웁니다. 사람이 열어 둔
  VISSIM 창에 붙어 작업을 덮어쓰는 일이 없습니다.
- **실행 후 거짓말 탐지**: "시뮬레이션이 끝났다"는 신호만 믿지 않고, 결과 파일 존재
  여부·차량 도착 수·평가 표 유무 등을 교차 확인합니다.
- **파일 기반 저장**: 별도 DB 없이 파일로 동작해 설치·백업이 단순합니다.
- **API 키 보안**: LLM 키는 git에서 제외된 `backend/.env`에만 존재합니다.

## 로컬 실행

Python 3.11+ 와 Node.js가 필요합니다. 터미널 두 개로 백엔드·프론트엔드를 각각 실행합니다.

```powershell
# 터미널 1: 백엔드
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8001
```

```powershell
# 터미널 2: 프론트엔드
cd frontend
npm install
npm run dev
```

- 웹 대시보드: `http://localhost:3000`
- 백엔드 API 문서: `http://localhost:8001/docs`
- AI 기능 사용 시: `backend/.env`에 `ANTHROPIC_API_KEY` 설정 필요
- VISSIM 없이 화면을 확인하려면: `python backend/tools/make_demo_data.py`로 합성
  데모 데이터를 생성할 수 있습니다 (시뮬레이션 실행 등 COM 기능 제외)

실제 시뮬레이션 실행·편집에는 PTV VISSIM(COM 라이선스 포함) 설치가 필요합니다.

- **완료**: 대시보드·검증 화면, AI 에이전트 v1(파라미터 수준 읽기 8종·쓰기 8종·실행),

  유/무 침묵-실패 검출률 60% vs 0%)

  실시간(시뮬레이션 중) 렌더링, 신호 상태 재생, 3D 뷰, 국내 교통 데이터 연동
