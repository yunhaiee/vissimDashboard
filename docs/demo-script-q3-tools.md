# Q3 새 도구 데모 스크립트 (2026-07-31)

8개 유닛에서 나온 새 도구를 채팅창에서 직접 시험하는 순서입니다. **거부(refusal)가 곧 제품**이므로,
이 스크립트는 일부러 거부를 여러 번 유도합니다 — 카드가 빨갛게 뜨는 게 정상이자 핵심 장면입니다.

**업데이트(07-31): COM 적용 문제 해결됨.** 원인은 파일의 시나리오 관리 플래그였고, 작업
사본에서 자동으로 정규화되도록 수정했습니다. **이제 2부의 모든 적용·롤백·배치 실행을 현재
Murdoch 모델에서 바로 진행할 수 있습니다** — 예제 네트워크 업로드는 더 이상 필요 없습니다
(2부의 프롬프트만 현재 모델의 객체 번호로 바꿔 쓰면 됩니다: 우선권 규칙 132~145, 주행 행동
101 복제 등). 백엔드는 이 수정 이후 재시작된 상태여야 합니다.

준비: 백엔드(:8001)·프론트(:3000) 실행 중, 어시스턴트 패널 열기, 에이전트 모드.
**백엔드는 반드시 최신 코드로 재시작된 상태여야 합니다** — 서버 프로세스는 시작 시점의
코드를 계속 쓰므로, 새 도구 커밋 이후 재시작하지 않으면 ⑥(주행 행동)과 ⑧(배치)의 도구가
"지원되지 않는다"고 답합니다 (2026-07-31 1차 시연에서 실제로 겪은 일).

*1차 시연 결과 메모: ①~⑤는 전부 기대대로 동작(③의 "Vissim은 조용히 허용하지만 이
시스템은 막습니다" 문구 포함). ①은 후보 목록 대신 곧바로 3형제 전체를 해석해 구간별
교통량까지 답했는데, 이는 기대보다 좋은 동작입니다. 부수 발견: 우선권 규칙 143의
링크/차로 정보가 비어 있음 — 모델 데이터 특이점, 확인 필요.*

## 1부 — 현재 Murdoch 모델에서 (지금 바로 됨)

### ① 같은 이름 객체의 후보 제안 (fuzzy-match 완전성)
> **차량 입력 Jenalup STWB의 교통량 알려줘** *(일부러 오타)*

기대: 못 찾았다는 답과 함께 후보 **6개 전부** — `107, 207, 307, 111, 211, 311`.
이전에는 각 이름당 첫 번째 것(107, 111)만 제안했습니다.

### ② 우선권 규칙 읽기 + 값 검증
> **우선권 규칙 목록 보여줘**

기대: 13개 규칙, 각 마커의 gap time(초)·min clearance(미터). "headway"가 사실 미터 단위
clearance의 별칭이라는 게 이번에 실측으로 밝혀진 내용입니다.

> **우선권 규칙 132의 갭 타임을 -1로 바꿔줘**

기대: **거부** — 음수 불가. (0은 실제 데이터의 최빈값이라 허용됩니다.)

### ③ 희망 속도 분포 — 곡선의 수학적 불변식
> **희망 속도 분포 목록 보여줘**

기대: 45개. **분포 60**에 주목 — 참조 136건(결정 120 + SLK 차종 조성 16). 이 참조 수가
다음 데모의 경고 근거입니다.

> **희망 속도 분포 60의 곡선을 (20km/h, 0), (60km/h, 0.8), (40km/h, 1)로 바꿔줘**

기대: **거부** — 속도가 중간에 감소(60→40). Vissim COM은 이런 곡선을 *조용히 받아들이므로*
이 거부는 우리 검증 계층만이 잡는 것입니다. 함께 뜨는 경고: 이 분포를 참조하는 결정
120건 + SLK 조성 16건 명시.

### ④ 차량 유형
> **차량 유형 목록 보여줘**

기대: 28개, 각 유형의 중량/출력/가감속 함수 참조가 이름으로 풀려서 표시.

> **차량 유형 200의 중량 분포를 999999로 바꿔줘**

기대: **거부** — 대상 분포가 존재하지 않음.

### ⑤ 시간 분포 (정차 시간) — 컨설팅 발견 포함
> **시간 분포 목록 보여줘**

기대: 10개. **주목: `BusDwell_0`~`BusDwell_4` 5개가 참조 0건** — 버스 정차 곡선을 만들어
놓고 어느 정류장에도 연결하지 않은 상태입니다. TK에게 보여줄 실제 발견.

> **시간 분포 10의 평균을 12초로 바꿔줘**

기대: 승인 카드 + **경고** — 이 분포 하나를 정류장 18곳이 공유. (취소해도 되고, COM 적용이
고쳐졌으므로 승인하면 실제 적용 후 read-back 값까지 카드에서 확인할 수 있습니다.)

> **시간 분포 34의 평균을 12초로 바꿔줘**

기대: **거부** — 34는 EMPIRICAL(곡선형)이라 평균/표준편차 편집 불가. Vissim 자체 규칙을
사전에 대신 말해주는 겁니다.

### ⑥ 주행 행동 — 공유 객체는 제자리 수정 불가
> **주행 행동 101의 ax를 2.5로 바꿔줘**

기대: **거부** — 101은 실제 도로(모든 주요 간선, 293개 링크의 유형)가 쓰는 살아있는
물리 파라미터. 메시지가 "복제 → 사본 수정 → 할당" 경로를 안내합니다.

### ⑧ 배치 계획 — 이번 큐의 하이라이트
> **차량 입력 107을 1000으로, 207도 1000으로 한 번에 바꿔줘**

기대: **계획 전체 거부** — 각 단계는 단독으론 통과하지만, 1단계의 의도값을 반영해 2단계를
검사하면 링크 620 총수요 1000 + 1000.95 > 용량 1900. **당신이 처음 신고했던 107/207/307
바로 그 객체들로, 단계별 검토로는 보이지 않는 합산 효과를 잡는 장면입니다.**

> **차량 입력 107을 300으로, 신호 제어기 6의 주기를 90으로 한 번에 바꿔줘**

기대: 승인 카드 하나에 두 단계의 diff가 모두 표시. (적용은 2부에서.)
*(이 모델의 신호 제어기 번호는 6/7/8/9/10/99 — 6번이 TCS398_MurdochDr. 초판 스크립트의
"제어기 1"은 존재하지 않는 번호였습니다. 존재하지 않는 번호로 시도하면 배치 검증이 해당
단계를 지목해 계획 전체를 거부하는 것도 그 자체로 좋은 데모입니다.)*

## 2부 — 실제 적용·롤백·배치 실행 (현재 Murdoch 모델에서 바로)

*(COM 적용 수정 이후에는 예제 네트워크 업로드가 필요 없습니다. 아래 프롬프트는 전부 현재
모델의 실제 객체 번호입니다.)*

### 우선권 규칙 실제 적용
> **우선권 규칙 132의 1번 마커 갭 타임을 3.0초로 바꿔줘** *(현재 2.5초)*

기대: 승인 → 적용 → **read-back 검증 값이 카드에 표시** (쓴 값과 다시 읽은 값 일치).

### 주행 행동 전체 흐름 (복제 → 수정 → 할당, 승인 3번)
> **주행 행동 101을 "시연용 사본"이라는 이름으로 복제해줘**
> **주행 행동 [새 번호]의 ax를 3.0으로 바꿔줘** *(참조 0건인 복제본이므로 이번엔 허용 — 원본 101의 현재값이 2.5라서 2.5로는 바뀔 게 없습니다)*
> **링크 행동 유형 101의 주행 행동을 [새 번호]로 바꿔줘**

### 롤백 — 잊지 않는 실행 취소
> **방금 편집 되돌려줘**

기대: 마지막 편집이 무엇이었는지 명시한 승인 카드 → 적용 → 바이트 단위 복원.
바로 한 번 더 시도하면 **거부** (연속 롤백 경계 — 한 단계만, 이유 설명 포함).

### 배치 성공 + 통째 롤백
> **차량 입력 107을 300으로, 207을 50으로 한 번에 바꿔줘** *(합산 351 < 용량 1900이라 통과)*
> → 승인 → 단계별 read-back 표시
> **방금 편집 되돌려줘** → **배치 전체가 한 번에** 되돌아감 (버전 1개 = 계획 1개)
