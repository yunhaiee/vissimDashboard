네트워크 프리뷰, 오른쪽 드로어를 나가면 어디로 가야 하나

현재 구조에 대한 지적을 받아, 편집 전 비교용으로 4안을 그렸습니다. 회색 상자 = 현재도 있는 요소, 초록 상자 = 지도, 파란 테두리 = 선택 상태.

현재의 문제: 이력 행을 누르면 오른쪽 46% 드로어에 판정 헤더 · 3×3 그리드 · 수정 카드 · 지도 · 아티팩트가 전부 세로로 쌓입니다. 지도는 언제나 좁은 폭 안에서 그리드 아래로 밀려 있고, 소견 위치를 지도에서 확인하는 순간 — 이 화면의 실제 용도 — 이 가장 갑갑합니다.
A

지도가 배경이 되는 오버레이형

행을 누르면 지도가 콘텐츠 전폭으로 깔리고, 판정(그리드·소견·수정 카드)은 지도 위 왼쪽에 뜨는 접을 수 있는 카드가 됩니다. GIS 도구의 문법 — 지도가 지면, 판정이 레이어.

새 생성 폼 + 생성 이력 (접힘 · 클릭 시 펼침)
지도 — 전폭 · 소견 하이라이트 · 클릭 선택
region_n36… 거부됨 판정 2·2·5 · V1–V9 그리드(축약) 선택 소견 · 수정 카드 · 아티팩트 ▾
  • 지도가 처음으로 주인공 — 소견 위치 확인이 한눈에
  • #19의 클릭 선택·폭 리본이 제값을 함
  • 판정 카드가 지도를 가림 — 그리드·수정 카드가 좁은 카드 안으로 돌아감(지금 드로어의 문제를 카드로 옮길 위험)
  • 폼·이력이 접히면 "다음 생성 시작"이 한 클릭 멀어짐
B

세로 흐름 단일 컬럼

분할을 버리고 작업 순서대로 위→아래: 폼 → 이력 → (선택 시) 판정 → 전폭 지도 → 아티팩트. 보고서처럼 읽힙니다.

C

전폭 상세 + 탭

행을 누르면 전폭 상세 영역이 열리고, 안에서 [판정] [지도] [아티팩트] 탭이 각자 전체 폭을 씁니다.

판정 지도아티팩트 region_n36… 거부됨

  • 수정 카드→재게이트 관전 같은 긴 흐름에서 탭이 계속 튐
D · 추천

상세 페이지로 승격 — 허브는 목록만

행 클릭 = /genesis/jobs/[id]로 이동. 허브는 폼+이력만 남고, 상세 페이지는 지도를 넓은 왼쪽(≈65%)에, 판정·소견·수정 카드를 오른쪽 좁은 레일에 둡니다 — 지금과 좌우가 뒤집히고, 판정 스택이 화면 하나를 온전히 씁니다.

지도 — 넓게 · 클릭 선택 ↔ 오른쪽 소견 연동
V1–V9 그리드 (3×3) 선택 소견 + 수정 카드(승인)
  • 지도가 크고, 판정과 지도가 동시에 보임 — 소견 클릭↔지도 하이라이트 왕복이 한 화면
  • 생성마다 URL — B4 데모·공유·버그 제보("이 생성 봐줘")가 링크 하나
  • 허브가 가벼워짐(폼+이력) · B5-2 수정 루프가 자랄 공간(재게이트 계보 등)이 생김
  • Console의 목록→상세 페이지 문법과 일치
  • 페이지 전환 1회 추가 (이력 행 간 빠른 비교는 뒤로가기/이력 재방문)
  • 구현 규모 중간 — 드로어 콘텐츠의 라우트 이동 + 딥링크 로딩 상태

추천은 D입니다. 이 화면의 실제 동선은 "소견을 읽고 → 지도에서 그 위치를 보고 → 수정을 승인"인데, 그 왕복을 한 화면에 넓게 유지하는 건 D뿐입니다(A는 카드가 지도를 가리고, C는 탭 전환이 동선을 끊습니다). 생성별 URL은 데모·협업에서 덤이 아니라 실익입니다. 차선은 A — 페이지 전환 없이 지도를 키우고 싶다면. B와 C는 이 워크플로에는 비추천 사유를 적어뒀습니다.

결정 주시면 해당 안으로 유닛을 스펙해 진행합니다. 아직 아무것도 편집하지 않았습니다.
