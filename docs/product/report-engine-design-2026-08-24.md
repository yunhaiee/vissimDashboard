> ("기존 회사/랩 보고서 스타일 자동 매칭 + 그림·그래프·표 풍부화로 전문적 보고서").
> 상태: 설계 초안 — 사용자 확정 후 유닛 분해.

## 원칙 (R4.0 그대로): 스타일은 피부, 뼈대는 규정

보고서의 콘텐츠 스파인은 MRWA가 요구하는 항목이 정의한다. 스타일 엔진은 그 스파인을
입히는 층이며, 스파인 없는 스타일링은 예쁜 빈 문서다. 따라서 순서는
**스파인 → 데이터 추출 → 스타일**이고, 각 층은 독립 유닛이다.

## 층 1 — 콘텐츠 스파인 (R4.0)

MRWA Operational Modelling Guidelines가 모델링 보고서에 요구하는 절 구조를
참조팩으로 전사(쪽 인용 탑재 — Table 5-6 전사와 같은 규율):
모델 목적·범위 → 네트워크 구축 근거 → 데이터(수요·신호·실측 출처) → 보정 결과
(GEH 표, 기준 충족 여부, critical 교차로 별도) → 검증 → 민감도/시나리오 → 부록
(승인 원장, 가정 목록, 게이트 리포트).

**이 제품의 강점을 스파인에 직결**: 각 절의 데이터가 이미 감사 가능한 형태로 존재한다 —
게이트 판정(V1–V9), 채점 리포트(GEH·rung), 승인 원장(서명·근거문), 탐색 원장(digest·
홀드아웃), 현시도 확인 기록(attestation). 보고서는 이들의 **뷰**이지 재입력이 아니다.

## 층 2 — 데이터 추출 + 도판 (R4.1/R4.2)

각 스파인 절에 들어가는 그림·표의 생성기 카탈로그:

| 도판 | 소스 | 형태 |
|---|---|---|
| GEH 노드 표 + 합격률 | reality_check 리포트 | 표 (critical 교차로 행 강조) |
| 노드 지도 (판정 칠) | 노드 좌표 + 판정 | 정적 지도 이미지 (Leaflet 서버 렌더 또는 SVG) |
| 전후 비교 차트 | 두 실행의 리포트 | 막대/산점 (GEH before/after) |
| 시계열 지체/대기열 | 결과 DB | 선 그래프 |
| Table 5-6 적용 표 | applied_rows 판정 | 표 (행 인용 포함) |
| 승인 이력 | 승인 원장 | 표 (누가·언제·왜·근거문) |
| 네트워크 도식 | shadow model | SVG (NetworkViewer 렌더 재사용) |
| 게이트 판정 요약 | gate.json | 표 + 소견 발췌 |

원칙: 도판마다 **출처 캡션**(실행 ID·데이터셋 revision·생성 시각)이 자동 부착 —
"이 그림은 어느 실행의 것인가"에 답 못 하는 도판은 방출하지 않는다.

## 층 3 — 스타일-from-샘플 (R4.3)

v1 = DOCX 한정 (HWP는 기존 도구 조사 후 별도 — 요구사항 12행의 방침 그대로).

1. **추출**: 과거 보고서 DOCX 업로드 → python-docx로 스타일 카탈로그 추출 —
   팔레트(제목/본문/강조색), 폰트 패밀리·크기 사다리, 로고(헤더 이미지), 제목 번호
   체계, 표 스타일, 여백/용지. 추출 결과는 **스타일 프로파일 JSON**으로 저장하고
   사용자에게 보여준다 (추출도 제안 — 틀리면 사람이 고친다, C1-b 문법).
2. **적용**: 새 보고서 생성 시 프로파일 선택 → 스파인+도판을 그 서식으로 조판.
   python-docx 스타일 정의 주입 (기존 exporters의 DOCX 조립 위에 스타일 층 추가).
3. **한계 정직**: 완전 복제가 아니라 "관례 일치"(팔레트·폰트·제목 구조·로고) —
   추출 불가 요소는 프로파일에 "추출 못 함"으로 명명.

## UI (/report 재편)

- 좌: 보고서 스파인 트리 (절별 포함/제외 토글, 절별 데이터 소스 상태 —
  "이 절의 증거 없음"은 회색+사유)
- 우: 미리보기 (절 단위)
- 상단: 실행/데이터셋 선택 + 스타일 프로파일 선택 (기본: Prism 기본 스타일)
- "생성" → DOCX (+ 도판 원본 zip 아티팩트)

## 유닛 분해 (제안)

| 유닛 | 내용 | 크기 |
|---|---|---|
| R-1 | 스파인 전사 (MRWA 보고 요구 → 참조팩, 쪽 인용) + 스파인 JSON | 중 |
| R-2 | 도판 생성기 4종 우선 (GEH 표·승인 이력·Table 5-6 표·게이트 요약 — 전부 표 기반, 저위험) | 중 |
| R-3 | 도판 생성기 그래픽 3종 (노드 지도·전후 차트·네트워크 SVG) | 중 |
| R-4 | 스타일 프로파일 추출기 + 프로파일 저장/표시 | 중 |
| R-5 | 스타일 적용 조판기 + /report UI 재편 | 대 |

순서: R-1 → R-2 → R-5의 UI 골격(기본 스타일) → R-3 → R-4 → R-5 완성.
R-2까지만 착지해도 "감사 가능한 표 중심 보고서"가 즉시 가치를 낸다 (요구사항의
"저위험, 매일 보이는 가치" 항목과 일치).

## 미결 (사용자 확인 필요)

1. 스파인의 MRWA 절 구조 — 참조팩 전사 시 어느 장을 기준으로 삼을지
   (op 가이드라인의 보고 요구 장 확인 필요; 없다면 TK에 1질문).
2. 스타일 샘플 — 실제 회사/랩 보고서 DOCX 1부 제공 가능 여부 (R4 추출기의
   실측 개발 대상; 없으면 합성 샘플로 개발하고 실물은 후속).
3. HWP 우선순위 — v1 제외 확정 여부.
