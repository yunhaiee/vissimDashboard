## 5. 작업 프로토콜 (이 세션에서 검증된 그대로)

**유닛 하나당**: 빌더(서브에이전트) → **적대적 검증(refuter)** → 수정 → 재검증 →
**오케스트레이터가 독립 재검증 후 커밋**(유닛 1개 = 커밋 1개, 서사형 메시지) → 로드맵 갱신.

**에이전트 금지 사항** (프롬프트에 매번 명시): git 상태 변경 금지(status/diff/log 허용) ·
`docs/`·CLAUDE.md 편집 금지 · `gate.py` 절대 금지(판사는 얼어 있음) · `runtime/` 수정 금지
(sqlite는 `immutable=1`로) · 라이브 COM 금지 · **테스트 포그라운드** · `data/` 편집 금지 ·
`make_demo_data.py` 메인 트리 실행 금지(라이브 대시보드가 읽는 파일을 덮어씀).

**병렬 패턴(이 세션에서 실증)**: 기본 직렬. 파일이 완전 분리된 유닛만 사용자 승인 하에 2개까지
병렬 — 백엔드/프런트 분리가 안전했고, 같은 파일을 다른 에이전트가 감사 중일 때는 **worktree
격리**(#46이 이 방식 — venv·client-data는 메인 절대경로로 읽기, 포팅 후 메인에서 재검증)가
정답이었음. 사용량 한도로 에이전트가 도중 사망하면(이 세션 1회 — API 521): 재작업 금지,
트리 감사 → 같은 에이전트에 SendMessage 재개. 컨텍스트를 아는 기존 refuter의 SendMessage
재활용이 신규 스폰보다 효율적(카드 시리즈에서 4회 실증).

**검증 기준선**: 백엔드 `4974/0/12` · 프런트 typecheck + contract **125** + build.
**contract 핀**: 재조준은 의미 유지, 새 핀은 변이 검증, 식별자는 단어 중간 파괴, 산문 주장은
산문 아닌 **코드에 결속**(#45의 verb 집합 스캔 패턴). **문자열**: ko 우선 + en/ja, 팔레트
동결(rose/emerald/sky), 오버레이는 리터럴 black.
