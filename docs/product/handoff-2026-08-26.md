## 0. 프로토콜 (축자 유지)

직접 코딩 금지. 빌더(sonnet 기본/난문 opus) → 반박자(변이는 실제 실행) → 오케스트레이터
독립 재검증(핵심 변이 1개 직접 재실행, cp+SHA256 백업·복원) → 1 유닛 = 1 커밋(서사형
영어 한 줄 + `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`) → push (사용자
상시 승인 있음). 반박자가 실결함을 내면 빌더에 되돌리고 수정분을 다시 공격시킨다.
에이전트 금지: git 상태 변경·docs/·CLAUDE.md·gate.py·runtime/·data/·본 트리
make_demo_data.py 수정·라이브 COM. 테스트 포그라운드. 프런트 빌더 프롬프트에
frontend/AGENTS.md 지시(node_modules/next/dist/docs/ 선독) 필수 탑재. 정찰 요약은
축자가 아니므로 어휘·상수는 소스에서 직접 확인. **절대 `git checkout --`을 미커밋
파일에 쓰지 마라** (이번 세션 실사고 — cp+SHA256이 표준).

**이번 세션 신설 — 워크트리 빌드 체제**: 사용자가 메인 트리 dev 서버로 라이브 데모
중이므로 모든 빌더/반박자는 `Agent isolation: "worktree"`로 격리 실행했다.
- 워크트리 테스트: 백엔드 = 메인 트리 venv 인터프리터를 워크트리 backend에서 실행
  (`C:\...\vissimDashboard\backend\.venv\Scripts\python.exe -m pytest`), 프런트 =
  node_modules를 PowerShell Junction으로 연결. 워크트리에 data/ 시드가 없으면 전체
  스위트가 소음(FileNotFoundError 다발) — 보고서·시뮬 계열은 타깃 스위트로 판정하고
  전체 검증은 랜딩 시 메인에서. (#59 빌더는 gitignored data/를 읽기 전용 복사해
  워크트리에서도 전체 6010/0을 얻었다 — 허용된 방법.)
- 워크트리 checkout은 autocrlf 때문에 CRLF로 실체화 → **계약 스위트에 CRLF 아티팩트
  실패 ~11–12개가 뜬다** (ModalDialog·#23·#29·#35·#42·#48-b·B5-2 등). 이름 집합을
  베이스라인으로 찍고 명단 비교로만 판정한다.
- **랜딩 절차 (실측으로 확정된 의식)**: ① 워크트리에서 `git -C <wt> diff` → 패치
  (untracked 신파일은 별도 cp) ② 메인에서 `git apply`(이동한 파일은 `-3`) ③ **적용된
  파일 전부 LF 정규화** — git apply가 autocrlf 스머지로 CRLF를 다시 써서 #42 CRLF-민감
  핀이 깨진다(실측, 254→255 복원) ④ 메인 전체 스위트(backend full + typecheck +
  contract) ⑤ 오케스트레이터 변이 1개 직접 재실행·격추 확인·해시 복원 ⑥ 로드맵 행
  뒤집고 커밋·푸시 ⑦ 백엔드 파일이면 preview_stop/start로 backend 재기동(프런트는 HMR).

## 4. 오늘 새로 배운 트랩 (전 계정 공유)

1. **git apply의 autocrlf 스머지**: 패치 적용이 파일을 CRLF로 다시 씀 → #42 CRLF-민감
   핀 파손. 랜딩 의식 ③(LF 정규화)이 해법. 커밋은 어차피 LF로 정규화되므로 내용 무해.
2. **반박자의 `git checkout --` 실사고**: 미커밋 빌더 작업을 날릴 뻔(SHA256 대조로
   복원, autocrlf LF→CRLF 변환까지 포렌식). cp+SHA256 백업이 의무.
3. **워크트리 CRLF 아티팩트**: 계약 스위트 판정은 실패 "이름 집합" 비교로만.
4. **변이 프로브는 코드 지점을 grep으로 먼저** (docstring 타격 2회 전과 — 08-24 기록).
5. **에이전트 경로 vs 화면 경로**: #59 반박이 보여준 패턴 — 화면 유도는 구조상 안전해도
   LLM이 직접 채우는 tool 파라미터 경로가 같은 불변식을 우회한다. 새 복합 구조를 만들면
   반드시 tool 문에서의 도달 가능성을 별도 공격할 것.
