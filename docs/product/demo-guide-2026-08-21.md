## 용어 4개 (데모 전에 딱 한 번)

- **GEH** — 모델 교통량과 실측 교통량의 차이를 재는 업계 표준 점수. **5 미만이면 합격**.
- **보정(캘리브레이션)** — 모델이 실측을 재현할 때까지 조정하는 일. 이 제품의 핵심.
- **현시도** — 신호가 어떤 순서로 켜지는지 그린 그림. 그림이라 기계가 못 읽고, 사람 확인이 필요.
- **게이트** — 생성된 모델이 통과해야 하는 자동 검증 관문(V1~V9). **거부가 제품이다**:
  Vissim은 조용히 틀리는데, 이 제품은 이유를 명명하며 거부한다.

     (실 Vissim 런 3회 + 6노드 실측 워크북 탑재)

## 장면 1 — 지도에서 영역을 그리면 모델이 생긴다 (프로젝트 "demo", ~7분)

[답하는 질문] "Vissim을 열 줄 몰라도 네트워크 모델을 만들 수 있나?"

1. 좌측 ① 네트워크 → **생성** (`/genesis`).
2. **영역에서 추출하기 →** → 지도에서 교차로 하나를 라쏘로 그린다(점 찍고 두 번 클릭으로 닫기).
   - 대안(오프라인 안전): 파일 업로드 경로로 폴더의 `01_데모영역_지도파일.osm`.
3. **영역 추출** → 초록 카드 → 생성 시작.
4. 잡 상세에서 ✓ **게이트 판정 V1~V9** — 통과/거부/확인 불가가 전부 **이유와 함께** 명명.
   지도에서 빨간 링크 클릭 → 소견 카드.
5. 말할 것: "거부가 뜨면 그게 기능입니다 — 조용히 틀린 모델이 최악이니까."
   소견에 **영역 편집 →** 버튼이 있으면: 경계를 늘려 재추출하는 ask-first 관문 시연.

## 장면 3 — 실측과 대조해 채점하고, 왜 틀렸는지 진단한다 (프로젝트 "라이브 데모 2026-08-07demo0821", ~8분) ★핵심

[답하는 질문] "내 모델이 현실을 재현하는지 어떻게 아나? 안 맞으면 뭘 해야 하나?"

이 프로젝트에는 실제 Vissim 런과 6노드 실측 워크북이 미리 들어 있다.

1. ③ 시뮬·보정 → **보정** (`/calibration`).
2. ✓ 상단 하늘색 배너: **"채점할 실행을 선택하세요"** — 화면이 항상 다음 행동을 말해준다.
3. 실행 선택 → ✓ 배너가 다음 할 일로 바뀜, 노드 타일 그리드:
   - **노드 4 = 빨강, GEH 7.51** (불합격 — 설계된 미스)
   - **노드 1·2·3·5·8 = 초록, GEH 0.0** (합격 대조군 5개)
4. 빨간 타일 클릭 → 진단: 이 미스가 진단 사다리의 어느 단인지 + 다음 행동.
5. 좌측 레일 = MRWA 지침의 13단계. ✓ 증거 없는 단계는 절대 "완료"로 표시되지 않음
   ("증거 없음"). 수동 확인 영역은 ∨ 화살표로 펼침.
6. 어시스턴트(우측 드로어)에 노드 4의 미스를 물어본다 (예: `노드 4가 왜 안 맞아?`) →
   ✓ 진단과 다음 행동이 **근거문과 함께 3개 언어로**. 실측 입구를 직접 고치라는 요청은
   **거부됩니다** — "실측은 목표값이지 조절 손잡이가 아니다"가 이 제품의 제1원칙.
7. 규칙 설명이 필요하면 우상단 책 아이콘(`/docs`) → 보정 워크스페이스 섹션 — 화면의 모든
   독트린이 문서로 이사했고, 화면에는 행동만 남았다 (#50-d).

## 장면 4 — 감이 아니라 표로 처방한다 (프로젝트 "라이브 데모 2026-08-07demo0824L", ~6분) ★업데이트

[답하는 질문] "파라미터 튜닝은 결국 감 아닌가?"

이 프로젝트(혼잡 장면 ×2.0 · 1시간 런)는 **실제 용량 한계 진단이 발화한 상태**로 미리
구워져 있다: 노드 8이 CAPACITY_LIMIT, 접근로 759가 LOS F(지체 229.8초). 900초 런에선
대기열이 진입점 밖에 갇혀 지체가 안 쌓였지만(물리 천장, LOS D 42.6초), 1시간 런은
그 대기열이 실제로 소화되며 지체를 적립한다 — 측정이 밝힌 사실 그 자체가 데모 소재.

1. 프로젝트를 **"라이브 데모 2026-08-07demo0824L"**로 전환 → `/calibration`.
2. ✓ 노드 8 타일 빨강 → 클릭 → 진단: **용량 한계(CAPACITY_LIMIT)** — 다음 행동
   "⑦ 포화교통류를 측정하라".
3. 좌측 레일 → **행태 파라미터** (⑫): ✓ Table 5-6 표 — 각 주행행태의 현재 값이
   **공표된 표의 어느 행 위에 있는지** 판정. (뜨는 경우) 회색 경고 "기본값 우연 일치 —
   측정 증거 아님".
4. 어시스턴트 드로어에 측정을 공급하며 처방을 요청:
   `노드 8이 용량 한계 진단이야. 정지선 포화교통류를 측정했어: 1780 pcu/h/ln,
   정지선 방출 헤드웨이 측정, 표본 8회 × 11대, Dochak 현장조사팀 2026-08-14 07:30-08:30.
   Table 5-6 차량추종 제안 만들어줘.`
5. ✓ **승인 카드**: ax 2.5 · bx_add 2.5 · bx_mult 3.5 (1780 pcu 행), 근거문에
   "MRWA Table 5-6, p.187" + 측정 출처·표본 + 양쪽 이웃 행 + 적용 범위 문장.
6. 말할 것: "측정값이 표의 행을 고르고, 표가 값을 정합니다. 감이 아니라 인용입니다.
   승인해도 공유 행태 가드레일이 반경을 전부 명명해야만 통과시킵니다."

재제조(필요 시, ~4분): `cd backend` 후
`.venv\Scripts\python.exe tools\calibration_loop_live_check.py --scene congested --demand-factor 2.0 --duration 3600 --stages 0,1,2 --label demo0824L`
→ 같은 커맨드로 `--stages 1,3 --expect car-following --saturation-flow 1780 --sf-method "정지선 방출 헤드웨이 측정 (MRWA Appendix B §B.3 on-site)" --sf-attribution "Dochak 현장조사팀" --sf-measured-at "2026-08-14 07:30-08:30" --sf-samples 8 --sf-vehicles-per-sample 11`

## 장면 6 — 지침 범위 안에서만, 기계가 대신 탐색한다 (~7분, 브라우저+터미널)

[답하는 질문] "진단·처방까지 했는데도 안 맞으면? 감으로 만지나?"

**브라우저 절반 — 문은 실재하고, 증거 없이는 안 열린다:**
1. `/calibration` → **행태 파라미터** (⑫) → 탐색 트랙.
2. ✓ 탐색 가능한 파라미터가 **딱 3개** (발주처 지침이 범위를 공표한 것만 — 차로변경
   안전계수 0.25–0.45 등). 나머지는 '자세히'에 제외 사유.
3. ✓ **탐색 시작 버튼이 실재** (이 머신에 러너가 배선됨 — 버튼이 비용을 말함).
4. 클릭 → ✓ **이유를 명명하며 거부** — 부족한 증거를 하나하나 이름으로 (신호 미검증 등).
   말할 것: "시작 버튼조차 증거 없이는 안 열립니다. 어떤 증거가 부족한지 문장으로
   말하는 것 — 이것이 이 제품의 방식입니다."

**터미널 절반 — 실제로 돌면 어떻게 되나 (미리 완주해 둔 증거, 원하면 라이브 ~15분):**
```
cd backend
.venv\Scripts\python.exe tools\parameter_search_live_check.py --stages 2 --label acc0821 --budget-s 14400 --behavior-no 1
```
5. ✓ 실측 결과 (2026-08-21 완주): **후보 18개 전부 실제 Vissim 런**, 실패 0, 잔존
   프로세스 0, 상태 COMPLETE. 그리고 결말: **승자 objective = 기준선과 정확 동률** →
   기계가 **무개선 제안을 거부** (HOLDOUT_NOT_IMPROVED — 아무것도 모델에 닿지 않음).
6. 말할 것: "18번 돌려보고 나아진 게 없자, 이 기계는 제안하지 않았습니다.
   **소음을 제안하지 않는 것** — 자동화의 신뢰는 여기서 나옵니다. 혼잡한 네트워크에서는
