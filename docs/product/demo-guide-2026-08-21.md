## 용어 4개 (데모 전에 딱 한 번)

- **GEH** — 모델 교통량과 실측 교통량의 차이를 재는 업계 표준 점수. **5 미만이면 합격**.
- **보정(캘리브레이션)** — 모델이 실측을 재현할 때까지 조정하는 일. 이 제품의 핵심.
- **현시도** — 신호가 어떤 순서로 켜지는지 그린 그림. 그림이라 기계가 못 읽고, 사람 확인이 필요.
- **게이트** — 생성된 모델이 통과해야 하는 자동 검증 관문(V1~V9). **거부가 제품이다**:
  Vissim은 조용히 틀리는데, 이 제품은 이유를 명명하며 거부한다.

## 장면 2 — 엑셀을 올리면 현시도가 그려진다 (프로젝트 "demo", ~3분) ★#55로 재작성

[답하는 질문] "손에 있는 현시도를 어떻게 모델의 신호로 만드나?"

1. ② 데이터 → **신호 (현시도)** (`/genesis/phases`).
2. ✓ 화면의 뼈대가 딱 두 개다: **템플릿 다운로드**와 **엑셀 업로드**. 판독을 심사하는
   검토 화면이 아니다.
3. 바탕화면 `대전현시도-정정본` 폴더의 엑셀 하나를 업로드 → ✓ 교차로 카드에 **현시도
   도식 + 신호 시간 테이블**이 나란히 그려진다(Φ1…Φn 스트립, 이동류별 화살표, 보행은
   머리 없는 횡단 바; 시간 테이블은 시트의 녹색/황색·주기·옵셋을 그대로). (#58)
   ✓ 대조할 것이 없는 업로드 판독에는 "기계 대조" 절 자체가 없다 — 빈 문구를 읽게
   하지 않는다.
4. 말할 것: "판독을 확인하는 클릭은 없습니다. 직접 채워 올린 표는 이미 그 사람의
   진술이니까요. 올린 사람과 시각은 서버가 찍습니다."
5. (#58) 시간 테이블의 **황색시간을 직접 고쳐본다** → ✓ 수정이 즉시 반영되고, 수정한
   사람·시각이 서버 기록으로 남는다(append-only — 이전 값은 지워지지 않는다). 말할 것:
   "이 숫자가 곧 황색 선언입니다. 대전 시트는 황색+전적색을 합쳐 인쇄하니까요."
6. ✓ 도식이 스스로 밝히는 정직 문구 3개를 짚는다:
   - **배치는 화면 배열이며 방위가 아니다** — 템플릿에 방위 열이 없으므로 접근로는 시트에
     적힌 순서대로 놓인다(스트립과 함께 항상 렌더, 툴팁이 아니다).
   - **'미상'은 화살표가 되지 않는다** — 방향을 모르는 이동류는 칩으로 남는다(코드에서
     타입 수준으로 막혀 있어, 여섯 번째 이동류가 생기면 컴파일이 깨진다).
   - 모델이 확정하지 못한 부분은 그 현시 밑에 **문장 그대로** 남는다.
7. 카드의 **네트워크 결박** 절을 펼친다 → ✓ (#58) **왼쪽 지도 / 오른쪽 내용** 분할:
   생성 작업을 고르면 draft 지도에 노드 후보가 떠서 **클릭으로 선택**한다(수준/계획은
   하나뿐이면 자동). 확인 행위는 **'확인' 한 단어 버튼 하나**. 말할 것: "표를 올리는 것과,
   그 표가 이 네트워크의 어느 노드인지 말하는 것은 다른 일입니다. 뒤쪽만 서명을
   요구합니다 — 클릭은 선택일 뿐, 서명은 확인 버튼뿐입니다."
   (결박 없는 매핑은 신호 생성이 여전히 거부한다.)

## 장면 3 — 실측과 대조해 채점하고, 왜 틀렸는지 진단한다 (프로젝트 "라이브 데모 2026-08-07demo0821", ~8분) ★핵심

[답하는 질문] "내 모델이 현실을 재현하는지 어떻게 아나? 안 맞으면 뭘 해야 하나?"

이 프로젝트에는 실제 Vissim 런과 6노드 실측 워크북이 미리 들어 있다.

1. ③ 시뮬·보정 → **보정** (`/calibration`).
2. ✓ 상단 하늘색 배너: **"채점할 실행을 선택하세요"** — 화면이 항상 다음 행동을 말해준다.
3. 실행 선택 → ✓ 배너가 다음 할 일로 바뀜, 노드 타일 그리드:
   - **노드 4 = 빨강, GEH 7.51** (불합격 — 설계된 미스)
   - **노드 1·2·3·5·8 = 초록, GEH 0.0** (합격 대조군 5개)
4. 빨간 타일 클릭 → 진단: 이 미스가 진단 사다리의 어느 단인지 + 다음 행동.
5. 좌측 레일 = MRWA 지침의 13단계. ✓ 증거 없는 단계는 절대 "완료"로 표시되지 않음
   ("증거 없음"). 수동 확인 영역은 ∨ 화살표로 펼침. (#53) 기계가 볼 수 없는 단계는
   **서명 증언**(사유 필수)으로 "확인됨(사람 증언)"까지 갈 수 있다 — 완료가 아니라
   증언이고, 기계 증거가 생기면 증언보다 우선한다.
6. 노드 4 타일 클릭 → ✓ (#56) 진단 문장이 정직하다: 이 노드 접근로에는 **차량 인풋
   후보가 0개**라 지정할 것이 없고, 다음 행동은 "관측 지점/site→node 매핑 보완"이다 —
   존재하지 않는 인풋을 지정하라던 옛 문구는 사라졌다.
7. 어시스턴트(우측 드로어)에 노드 4의 미스를 물어본다 (예: `노드 4가 왜 안 맞아?`) →
   ✓ (#56) 어시스턴트가 **유도 감사 도구**로 거부 사유·후보 목록을 한 번에 읽어 답한다
   — 예전처럼 같은 도구를 반복 호출하다 6회 한도를 태우지 않는다. 실측 입구를 직접
   고치라는 요청은 여전히 **거부됩니다** — "실측은 목표값이지 조절 손잡이가 아니다".
8. 규칙 설명이 필요하면 우상단 책 아이콘(`/docs`) → 보정 워크스페이스 섹션 — 화면의 모든
   독트린이 문서로 이사했고, 화면에는 행동만 남았다 (#50-d).

## 장면 4 — 감이 아니라 표로 처방한다 (프로젝트 "라이브 데모 2026-08-07demo0824L", ~6분) ★업데이트

[답하는 질문] "파라미터 튜닝은 결국 감 아닌가?"

이 프로젝트(혼잡 장면 ×2.0 · 1시간 런)는 **실제 용량 한계가 물리적으로 발화한 상태**로

갇혀 지체가 안 쌓였지만(물리 천장, LOS D 42.6초), 1시간 런은 그 대기열이 실제로 소화되며
지체를 적립한다 — 측정이 밝힌 사실 그 자체가 데모 소재.

1. 프로젝트를 **"라이브 데모 2026-08-07demo0825"**로 전환 → `/calibration` → 실행 선택.
2. ✓ 노드 8 타일 빨강(GEH 35.3) → 클릭 → 진단: **분류 불가** — 자동 유도가 이 노드로

   현재 교통량·링크; 화면은 후보를 발명하지 않는다). **인풋 113 · 링크 617** 선택,
   사유 입력(예: `링크 617이 노드 8 도달 유입의 대부분 — 커넥터 그래프 확인`) → 지정.
4. ✓ 화면이 재조회되며 노드 8 진단이 **용량 한계(CAPACITY_LIMIT)** 로 재분류 — 다음 행동
   "⑦ 포화교통류를 측정하라". 기록에는 지정자·시각이 **서버 스탬프**로 남고(요청 본문은

5. 좌측 레일 → **행태 파라미터** (⑫): ✓ Table 5-6 표 — 각 주행행태의 현재 값이
   **공표된 표의 어느 행 위에 있는지** 판정. (뜨는 경우) 회색 경고 "기본값 우연 일치 —
   측정 증거 아님".
6. 어시스턴트 드로어에 측정을 공급하며 처방을 요청:

   정지선 방출 헤드웨이 측정, 표본 8회 × 11대, Dochak 현장조사팀 2026-08-14 07:30-08:30.
   Table 5-6 차량추종 제안 만들어줘.`
7. ✓ (#56) 어시스턴트가 **실행 ID를 되묻지 않는다** — 페이지가 선택된 실행을 컨텍스트로
   실어 보내므로 프롬프트 한 번에 승인 카드까지 간다. (표시 이름을 붙여넣어도, 유일하면

8. ✓ **승인 카드**: ax 2.5 · bx_add 2.5 · bx_mult 3.5 (1780 pcu 행), 근거문에

9. 말할 것: "측정값이 표의 행을 고르고, 표가 값을 정합니다. 감이 아니라 인용입니다.

## 장면 6 — 지침 범위 안에서만, 기계가 대신 탐색한다 (~7분, 브라우저+터미널)
